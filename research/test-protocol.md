# 点点跨端连续性测试协议

版本：2026-11-03。对象仅为**小红书 App 内置点点**与**点点 PC Web**，不包括独立点点 App。

## 记录前置条件

每轮先记日期时间与时区、手机系统和小红书 App 版本、PC 浏览器版本、两端是否登录同一小红书账号、是否有多个工作空间或账号切换。公开证据中不要写手机号、账号 ID、私人聊天内容；截图先遮盖识别信息。测试文本使用无个人信息的短标记，例如 `DOTS_T01_日期_随机后缀`。

「可见」指目标设备能从会话列表进入同一会话，看到完整测试标记及消息顺序；仅能通过手动复制文本到另一端，不算同步。每项都记录等待时间、刷新前后差异与失败提示。不要为了测试执行任何删除真实会话的操作。

| ID | 步骤摘要 | 观察点 | 状态 |
| --- | --- | --- | --- |
| T01 | 手机端新建测试会话，PC 同账号查找 | 会话列表、内容、首次出现时间 | [User-tested：目标端未出现，范围受限](test-results.md) |
| T02 | PC 新建测试会话，手机端查找 | 反方向是否可见 | [User-tested：目标端未出现，范围受限](test-results.md) |
| T03 | 选一条已有手机会话，在 PC 查找 | 新旧会话是否有差异 | 未运行 |

| T05 | 在手机测试会话发送第二条消息，PC 查看 | 已存在会话是否增量更新 | 未运行 |

首次「看不到」只能记录为该条件下未观察到，不能直接判定全体用户不能同步或断定后台根因。若某步骤无可操作入口，记为「未运行：入口不可用」，不要填成失败。

## 探索性 T09：交流提示框与 Web 内容的关联

这项测试是收到新观察后补充的探索项，不改变 T01–T08 主矩阵。

1. 已确认用户观察的是点点的**推荐提问**。先截图记录更新后的推荐原文与时间；若有更新前截图，也保留作基线。已出现的第三方工具话题要单列为初始观察，不能事后当作有对照的试验。具体名称仅留在本地未公开记录。
2. 在 PC Web 端创建不含个人信息的测试对话，使用一个自然但不常见的中性短语，例如「蓝色纸船七十三号」；不要在其他入口输入该短语。记录发出时间。
3. **不再更新 App**，观察同一推荐提问位置是否出现该短语或高度具体的同义内容，记录等待时长、是否刷新/重启 App，并截图。再换第二个短语重复一次；保留没有出现的结果。
4. 比较测试前的提示框与两次测试后的提示框。若只出现常见主题词，仍可能是推荐巧合；若独特短语在多轮测试后按时间顺序出现，可记为「跨端提示信号关联」，但**不能**直接认定聊天历史、完整 Agent Context 或后台存储已经同步。

全程避免使用真实私人聊天作为测试材料；截图遮盖账号和通知中的私人信息。若提示框无法稳定复现，记为「观察未复现」，不要倒填为失败。
