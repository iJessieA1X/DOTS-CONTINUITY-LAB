# 点点跨设备连续性研究｜阶段性报告

更新：2026-11-03。**这是阶段性判断，不是最终现状结论。** 妳已按同一账号、所称最新版 iOS App 与当前 Web 执行 T01/T02，两个方向的新会话在目标端均未看到；数字版本、等待与刷新条件仍未知，不能把观察写成全体用户的产品缺陷。

## 结论先行

值得解决的产品问题是：用户在小红书 App 内置点点捕捉想法后，能否在 PC Web 围绕同一目标继续。**第一步先解决同一账号、同一会话的双向可见与继续。**现有公开材料能确认点点 PC Web 入口存在、部分移动端入口之间有聊天记录同步的发布说明；**尚不能确认内置端与 PC Web 的历史互通范围及具体表现**。妳的 T01/T02 结果足以支撑这版问题与概念方案；若要进一步判断失败条件，优先补刷新后的结果。

妳又观察到：只在 PC Web 问过一次某第三方工具安装，更新 iOS App 后，点点的推荐提问立即出现该工具名称 [E-013](evidence-ledger.md)。这与会话列表不可见并不矛盾：推荐可能使用账号级兴趣信号，同时不展示完整会话。但 App 更新会刷新推荐，也可能是巧合；没有更新前基线或重复对照。新增 [T09 探索性对照](test-protocol.md)；在复现前不将它写成已验证的跨端 Context 能力。具体词句留在本地未公开记录中。

## 竞品参照

ChatGPT 与 DeepSeek 官方材料明确描述跨设备或跨平台的聊天记录同步；Gemini 的历史可用性受账号与 Keep Activity 设置影响；Claude Cowork 的云端任务可跨设备继续，但旧本地任务和本地文件能力有设备条件。详见 [Benchmark](benchmark.md)。这些案例支持三层连续性作为设计框架，也提醒我们把账号、数据范围和运行位置写清楚。它们不构成点点现状证据。

## 根因假设树

| 假设 | 可观察区分信号 | 测试 |
| --- | --- | --- |
| H01 PC Web 暂未覆盖内置端历史 | 同账号新旧会话双向不可见 | T01–T04 |
| H02 身份或会话归属不同 | 登录方式或账号不一致；切换后结果变化 | T01、T02、T08 |
| H03 用户资产可跨端但会话隔离 | 笔记/收藏可见，聊天不可见 | T03、T06 |
| H04 历史迁移范围有限 | 新会话可见，旧会话不可见 | T01–T03 |
| H05 方向性接口或权限差异 | 手机→PC 与 PC→手机结果不同 | T01、T02、T05 |
| H06 缓存或实时更新异常 | 刷新/重新登录后内容出现 | T04、T08 |

以上全部是 **Hypothesis**，测试只能改变优先级；即使观察到方向性差异，也不能黑盒断言数据库、API 或身份映射的内部结构。T07 若因目标会话不可访问而无法运行，应标记 `Blocked by History Unavailable`，不把它统计为独立的 Context 失败。
